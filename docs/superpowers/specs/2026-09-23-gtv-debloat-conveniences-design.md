# gtv-debloat Conveniences — Design Spec

**Date:** 2026-09-23
**Status:** Approved
**Author:** emrecan.bilgili

## Purpose

The core tool works and is verified on a real Arçelik Google TV, but real-world
use exposed one dominant friction: **getting connected over ADB**. Android 11+
Wireless debugging requires a manual `adb pair` + `adb connect` dance with
rotating ports, a flaky connection, and a protocol-fault on first pair. Users
also had to type a long Python path. This iteration removes that friction and
adds small quality-of-life features. All additions are additive and must not
weaken the existing safety invariants.

## Safety invariants (unchanged, never weakened)

- Never `pm uninstall` / `adb uninstall` — disable only (`pm disable-user --user 0`).
- Whitelisted packages never selectable/disabled (filtered in `selectable_packages`,
  re-checked in `disable_packages`).
- Uncatalogued ("unknown") packages require explicit `yes` confirmation.

## Features (priority order)

### 1. Guided pairing (`--pair`)

A `--pair` flag runs an interactive wizard so the user never memorizes adb:

- Prompt for the pairing endpoint (`IP:PORT` from the TV "pair with code" popup)
  and the 6-digit code.
- Run `adb pair IP:PORT CODE` (inline code form — avoids the interactive-prompt
  protocol fault). Retry once on `protocol fault` after `adb start-server`.
- On success, prompt for the connect endpoint (`IP:PORT` from the main Wireless
  debugging screen), run `adb connect`, and verify with `adb devices`.
- Then continue into the normal disable flow, auto-targeting the connected device.

New function: `pair_device(pair_endpoint, code) -> bool`. Prompts live in `main`.

### 2. `run.bat` launcher

A double-clickable Windows launcher that locates a working Python (try `py -3`,
then `%LOCALAPPDATA%\Programs\Python\Python312\python.exe`, then `python`),
runs `gtv_debloat.py` forwarding any arguments, and `pause`s at the end so the
window stays open. Documented in the README ("double-click to run").

### 3. `--all-safe`

Non-interactive bulk disable: target every installed package that the catalog
lists with `risk == "safe"`, skip the menu, print the list it will disable, run
`disable_packages`, print the summary. No `yes` gate needed (all are `safe`).
The `is_protected` double-guard in `disable_packages` still applies.

### 4. Polish

- `--version` flag prints `__version__` ("0.1.0") and exits.
- `.github/ISSUE_TEMPLATE/`: `package-suggestion.md` and `bricking-report.md`.
- README: add a "Quick start" section and document `--pair`, `--all-safe`,
  `run.bat`. (No fabricated GIF; leave recording to the maintainer.)

## Architecture

All logic stays in the single `gtv_debloat.py`. New pure/testable helpers:
`pair_device()`, and an `--all-safe` selection path reusing `load_catalog` +
`selectable_packages`/catalog. `main` gains three flags (`--pair`, `--all-safe`,
`--version`). `run.bat` and the issue templates are new files.

## Testing

Mock `adb`/`subprocess` throughout — no real device.

- `pair_device`: success path (pair ok → returns True), protocol-fault-then-retry,
  failure path (returns False).
- `--all-safe`: selects only catalogued `safe` packages present on device; never
  a protected one; calls `disable_packages` with exactly those.
- `--version`: prints version and exits 0 without touching adb.
- All existing tests keep passing.

## Non-goals (YAGNI)

- No GUI. No auto-QR pairing. No persistent config file (last-serial memory
  dropped — `--pair`/auto-select already remove the retyping pain).
- No real GIF asset generated by the tool.
